# Implementation Plan: Weekly Report Dashboard -- Trend and Carry-Over View

**Branch**: `001-weekly-report-dashboard`
**Spec**: `specs/001-weekly-report-dashboard/spec.md`
**Inputs**: `specs/requirements.md`, `specs/design.md`
**Date**: 2026-08-01

## Summary

Build a four-stage Python generator (ingest, canonicalize, validate, emit) that
reads the thirteen-week weekly report corpus and six metrics bundles and emits a
single self-contained dark-mode `index.html` with the chart library inlined.

The canonical table is computed once in Python and embedded as one JSON literal.
The browser never recomputes it; every figure is a projection over that table.
This is the structural enforcement of Constitution Principle I.

Two problems drive the design. First, no cross-week view exists, which has been
a carried item for four consecutive weeks. Second, commit-based metrics silently
misrepresent weeks of uncommitted work, proven by the 2026-08-01 week where 110
of 122 sessions produced no commits while the week's largest deliverable sat
untracked.

## Technical Context

**Language/Version**: Python 3.11+ (standard library only)

**Primary Dependencies**: Apache ECharts 5.x, vendored and inlined. No Python
dependencies beyond the standard library.

**Storage**: Filesystem. Markdown reports and JSON bundles as read-only input;
one HTML file as output. No database.

**Testing**: pytest, matching the existing convention in `model-scan`

**Target Platform**: Desktop browser, opened from local disk with no network

**Project Type**: Single project — CLI generator producing a static artifact

**Performance Goals**: Full regeneration of 52 weeks under 30 seconds; page
interactive under 2 seconds from disk

**Constraints**: Offline-only at runtime; page weight under 3 MB; byte-identical
output for unchanged input; read-only with respect to the report corpus

**Scale/Scope**: 13 weeks today, correct to at least 104 without redesign;
roughly 8 source modules and 4 figures

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Gate | Design compliance |
| --- | --- | --- |
| I. Canonical Table First | No chart code before the table validates and prints | Phase 1 completes and tests the data layer; Phase 3 introduces the first figure. Enforced by phase ordering, not convention. |
| II. Missing Is Not Zero | No null-to-zero coercion anywhere | `uncommitted_changes` and all bundle-derived fields are nullable; `missing_fields` is a required column; assertion A-004 enforces it |
| III. Provenance On Every Number | Every metric carries source, timestamp, quality | `source_bundle`, `retrieved_at`, `data_quality` are required WeekRecord fields; tooltips surface them |
| IV. Isolate Per-Item Failure | One bad record cannot abort the run | Every reader returns `(value, problems)` and never raises; integration test injects a malformed bundle |
| V. Self-Validating Output | Assertions emitted as data; non-zero exit on failure | `validate.py` returns `ValidationAssertion[]`; embedded in the page; `--check` gates |
| VI. Legibility Is Correctness | No overlapping labels, no color-only encoding | ECharts `labelLayout.hideOverlap` and `emphasis.focus`; marker shape varies with color; every figure has a data table |
| VII. Evidence Over Impression | No fitting, smoothing, or interpolation | `connectNulls: false`; assertion A-007; no regression code exists to review |

**Result: PASS.** No violation requires justification. No entry in Complexity
Tracking.

Re-check after Phase 1 design: pending.

**Structure decision**: Single project. The generator is a CLI producing a
static artifact; there is no service, no frontend build, and no API. Splitting
into packages would add ceremony without separation benefit.

## Phasing

Phases map to the user story priorities and each ends at a verifiable gate.

| Phase | Delivers | Stories | Gate |
| --- | --- | --- | --- |
| 1 | Data layer: ingest, canonicalize, validate | foundation | Canonical table correct against real corpus; all assertions pass; zero writes to corpus |
| 2 | Static emission without figures | US5 | Opens offline; byte-identical on repeat run; coverage panel correct |
| 3 | Figures 1-4 with ECharts | US1, US2 | AS-1..AS-4 demonstrable; 2026-08-01 flagged dark-work |
| 4 | Carry-over ledger and prose | US3, US4 | Trend item shows carry age 4; prose renders escaped and scrubbed |
| 5 | Integration into the suite skill | — | One command regenerates from clean checkout; single-week renderer retired |

Phase 1 must fully pass before Phase 3 begins. This is the Principle I gate and
is the main structural constraint on task ordering.

## Complexity Tracking

No constitutional violations. No complexity requiring justification.

One deliberate cost is recorded rather than justified as an exception: vendoring
ECharts consumes roughly 1 MB of the 3 MB page budget. The alternative is a CDN
reference, which NFR-020 forbids. Accepted knowingly per TDR-002.
